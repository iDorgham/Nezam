   - Add frontmatter to `MASTER_PLAN_v3.2.md`:
     ```markdown
     ---
     canonical: true
     supersedes: ['v0.3.5', 'v3.0']
     last_updated: 2026-06-06
     next_review: 2026-06-20

   - Update MEMORY.md to explicitly state: "MASTER_PLAN_v3.2.md is the ONLY active planning document"
   - Link all phase refs to v3.2-P1..P6 in TASKS_v3.2.md

3. **Consolidate task registry** (2 hours)

### 2. 🔴 Manual Sync Process (No CI Gate)

**Current State:**
- `CLAUDE.md` is auto-generated from `.cursor/` folders by `sync-ai-folders.js`
- Sync requires manual run: `pnpm ai:sync` + `pnpm ai:check`
- **CLAUDE.md is checked into git** (should only be generated)
- No GitHub Actions workflow validates sync before merge
- Drift undetectable until runtime when agents/rules unavailable

**Why It Matters:**
- Developer forgets `pnpm ai:sync` → .cursor/ changes silently ignored
- CI doesn't catch stale CLAUDE.md → production deployment with old agent definitions
- `.cursor/rules/*.mdc` edits aren't enforced → rules may contradict CLAUDE.md

**Remediation (Week 1, parallel with issue #1):**
1. **Move CLAUDE.md out of source control** (1 hour)
   - Remove `CLAUDE.md` from git: `git rm --cached CLAUDE.md`
   - Add `CLAUDE.md` to `.gitignore`
   - Create `CLAUDE.md.template` in `.cursor/` as documentation only
   - Update README: "CLAUDE.md is auto-generated; edit `.cursor/` files instead"

2. **Create GitHub Actions CI gate** (3 hours)
   - New workflow: `.github/workflows/ai-sync-validation.yml`
     ```yaml
     name: AI Sync Validation
     on: [pull_request, push]
     jobs:
       sync-check:
         runs-on: ubuntu-latest
         steps:
           - uses: actions/checkout@v4
           - uses: pnpm/action-setup@v2
           - uses: actions/setup-node@v4
           - run: pnpm install
           - run: pnpm ai:sync
           - run: pnpm ai:check
           - name: Fail if CLAUDE.md changed
             run: |
               git diff --exit-code CLAUDE.md || \
               (echo "❌ CLAUDE.md changed. Run 'pnpm ai:sync' locally and commit." && exit 1)
     ```
   - This ensures sync always runs and changes are detected

3. **Add pre-commit hook (Husky)** (1 hour)
   - If Husky not active: `pnpm husky install`
   - Create `.husky/pre-commit`:
     ```bash
     #!/bin/sh
     echo "🔄 Running AI sync validation..."
     pnpm ai:sync && pnpm ai:check || exit 1
     ```
   - Prevents developer from committing without sync

4. **Document workflow** (1 hour)
   - Add to `docs/CONTRIBUTING.md` (or create):
     ```markdown
     ## Making Changes to AI Configuration
     
     If you edit `.cursor/commands/`, `.cursor/agents/`, `.cursor/skills/`, or `.cursor/rules/`:
     1. Run `pnpm ai:sync` locally
     2. Commit both your changes AND the regenerated `CLAUDE.md`
     3. The pre-commit hook and CI will validate automatically
     ```

**Owner:** Devops Manager  
**Blocker:** Must complete before any `.cursor/` edits  
**Validation:** Try editing a `.cursor/` file without running sync → CI should fail

### 3. 🔴 RAM Bloat (30GB Index)

**Current State:**
- `.cursor/design/references/` contains 28 full Git repositories
- `.nezam/design-hub/node_modules/.pnpm/` contains ~500+ subdirectories (Tailwind cache)
- Both folders indexed by IDE → 30GB RAM usage on startup
- Slow Cursor/Claude Code performance, high memory pressure

**Why It Matters:**
- IDE becomes unusable with large projects open
- Claude Code context degraded by indexing overhead
- New team members experience steep onboarding friction

**Remediation (Week 1-2):**
1. **Move design references out of source tree** (2 hours)
   - Create external reference repo: `https://github.com/YOUR_ORG/nezam-design-references`
   - Move `.cursor/design/references/` → external repo `refs/`
   - Replace with Git submodule (optional) or documented external clone location
   - Update `.gitignore`:
     ```gitignore
     .cursor/design/references/
     .nezam/design-hub/node_modules/
     ```

2. **Automate reference updates** (2 hours)
   - Create script: `.nezam/scripts/sync-design-refs.sh`
     ```bash
     #!/bin/bash
     # Clones latest design references if not present
     REFS_DIR=".cursor/design/references"
     if [ ! -d "$REFS_DIR" ]; then
       git clone https://github.com/YOUR_ORG/nezam-design-references "$REFS_DIR"
     else
       cd "$REFS_DIR" && git pull && cd -
     fi
     ```
   - Call in `package.json` postinstall hook:
     ```json
     "postinstall": "pnpm run sync:design-refs"
     ```

3. **Prune node_modules** (1 hour)
   - Add to `.gitignore`: `node_modules/`, `.pnpm/`
   - Regenerate: `pnpm install` (should already work from lockfile)
   - Remove `.pnpm/` artifacts using: `pnpm store prune`

4. **Document setup** (1 hour)
   - Add to `CONTRIBUTING.md`:
     ```markdown
     ## First-Time Setup
     
     After cloning, run:
     ```bash
     pnpm install
     pnpm run sync:design-refs
     ```
     ```

**Owner:** Devops Manager / Lead Frontend Architect  
**Timeline:** 4-6 hours, can run in parallel with issue #1 and #2  
**Validation:** Repo size should drop from ~5GB+ to <500MB; IDE startup < 10s

### 5. 🟡 Phase Numbering Inconsistency

**Current State:**
- MASTER_PLAN_v3.2.md uses: `v3.2-P1`, `v3.2-P2`, ..., `v3.2-P6`
- TASKS_v3.2.md uses: Task format `T-P0-001`, `T-P0-002` (references v3.0 P0)
- PHASE_AUTOMATION.md may use different scheme
- P0 (Foundation) tasks reference "v3.0" — conflict with v3.2 namespace

**Why It Matters:**
- Ambiguity in task assignment: Is `T-P0-001` in v3.0 or v3.2?
- Status rollups fail without consistent naming
- Phase dependency chains unclear

**Remediation (Week 2):**
1. **Standardize all phase IDs to v3.2 namespace** (2 hours)
   - P0 is unchanged (Foundation, completed in v3.0, carried forward)
   - v3.2 phases: `v3.2-P1` through `v3.2-P6`
   - All tasks use format: `T-P0-NNN` for foundation, `T-v3.2-PN-NNN` for phase tasks
   - Update MASTER_PLAN_v3.2.md task table:
     ```
     T-P0-001, T-P0-002, ... (foundation)
     T-v3.2-P1-001, T-v3.2-P1-002, ... (P1 tasks)
     T-v3.2-P2-001, ... (P2 tasks)
     etc.
     ```

2. **Update phase dependency docs** (1 hour)
   - Add to MASTER_PLAN_v3.2.md:
     ```markdown
     ## Phase Dependency Chain
     - v3.2-P1: Foundation (sequential, must complete first)
     - v3.2-P2, v3.2-P3, v3.2-P4: Parallel start after P1 done
     - v3.2-P5: Parallel with P4
     - v3.2-P6: After P1-P5 complete
     ```

3. **Add validation script** (1 hour)
   - Script: `.nezam/scripts/check-phase-ids.sh`
     - Grep for stray `P0`, `P1`...`P6` without v3.2 prefix
     - Validate task ID format: `T-[v3.2-]P\d+-\d{3}`
     - Add to CI

**Owner:** Swarm Leader  
**Blocker:** After issues #1 and #4
