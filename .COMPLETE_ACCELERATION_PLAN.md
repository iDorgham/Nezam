## Unified Three-Command System

### Command 1: `/plan [type] [brief]`

**What it does:**
```
Input: /plan web-app "User authentication with OAuth"

Auto-detects:
  Type: Web Application
  Flow: Planning → API Design → Frontend Arch → Design → Dev → Release
  Timeline: 3 hours

Generates:
  ✅ PLANNING_BRIEF.md
  ✅ API_DESIGN.yaml
  ✅ FRONTEND_ARCHITECTURE.md
  ✅ DESIGN_SPECS.md
  ✅ REQUIREMENTS.yaml (context-injected)
  ✅ ADRs (locked via /decide)
  
Output: Complete spec with zero gaps
Time: 3h (automated)
Next: Ready for /develop
```

**Works for all 10 application types:**
- Web Apps (SaaS, dashboards, tools) → 3h
- Websites (marketing, blogs) → 5h
- Mobile Apps (iOS/Android) → 2.5h
- CLI Tools (command-line utilities) → 0.75h
- Backend Services (APIs, microservices) → 2h
- Batch Jobs (cron, scheduled tasks) → 0.5h
- npm Packages (libraries, SDKs) → 1h
- Extensions (browser, plugins) → 1h
- CMS Content (plugins, templates) → 1h
- Data Pipelines (ETL, analytics) → 1h

### Command 2: `/develop [feature-name]`

**What it does:**
```
Input: /develop web-oauth

Auto-loads context:
  ✅ Requirements from spec
  ✅ Design tokens + mocks
  ✅ API contracts
  ✅ Test templates

Auto-generates:
  ✅ Component skeleton (50% of code)
  ✅ Test stubs (100% coverage boilerplate)
  ✅ Type definitions
  ✅ Mock API responses

Opens IDE with:
  ✅ Feature branch created
  ✅ TODO comments marking what to code
  ✅ Documentation context sidebar
  
Result: Developer codes only the logic
Time: 0 setup friction
Next: Ready for /gates
```

**Per-type customization:**
- Web App → React/Vue skeleton + API client + tests
- CLI → Arg parser + command handlers + tests
- Mobile → Native screen + navigation + tests
- Backend → Endpoint handler + validation + tests
- Package → Export function + JSDoc + tests

---

### Command 3: `/ship [feature-name]`

**What it does:**
```
Input: /ship web-oauth

Auto-runs gates (parallel):
  ✅ Lint (with auto-fix)
  ✅ Test (with coverage check)
  ✅ Security scan
  ✅ Type check
  ✅ [Type-specific gates]

If all pass:
  ✅ AC validator (auto-verify acceptance criteria)
  ✅ Merge to main
  ✅ Deploy to staging
  ✅ Run smoke tests
  ✅ Deploy to prod (or queue for app store)

If any fail:
  ✅ Auto-suggest fixes
  ✅ Retry on fix
  ✅ Or block with clear reason

Result: Feature in production
Time: 5 min (fully automated)
Next: Done ✨
```

**Type-aware release:**
- Web App → Deploy to staging → prod
- CLI → Publish to npm → notify users
- Mobile → Submit to app stores
- Backend → Deploy to cloud
- Batch → Schedule on cron
- Package → Publish + version bump

## FAQ

**Q: Do we start using adaptive SDD immediately?**  
A: No. Finish P1 with current SDD + Silent Ops (faster anyway). Start adaptive for P2-P4.

**Q: What if we don't have time to build all 11 agents?**  
A: Build core agents first (Planning, Code-Gen). Batch/CLI agents later (higher ROI for v3.2 is web-focused).

**Q: Can we use this for existing codebases?**  
A: Yes. Start with `/plan web-app [feature]` for any new feature, regardless of existing code.

**Q: Will developers need training?**  
A: Three commands: `/plan`, `/develop`, `/ship`. That's it. Learn in 5 minutes.

**Q: What if a feature doesn't fit one type?**  
A: Most features are one type. For hybrid (e.g., web app + API), use web-app type (superset).

**Q: How do we handle custom ADRs per feature?**  
A: `/plan` auto-generates 7 critical ADRs. Customize via `/decide ADR-X "Custom Option"`.
