## Key Innovation: Context Injection

Every requirement now includes **WHY**:

**Before:**
```
AC-001: User can log in
  Given: User on login page
  When: Enters email + password
  Then: Redirected to dashboard
```

**After:**
```
AC-001: User can log in via OAuth
  Given: User is not logged in + has Google account
  When: Clicks "Sign in with Google" + grants permission
  Then: Redirected to dashboard + token in httpOnly cookie
  
  Context: |
    Why OAuth? Reduces friction, outsources security to Google
    Why httpOnly? Prevents XSS access, browser-managed
    What breaks if missing? Users frustrated, try password recovery
    Security implications: Token expiry 30d, refresh rotation
    Testing: Unit + integration + E2E coverage
```

**Result:** Developer sees the full picture. Zero "why is this this way?" delays.

## FAQ

**Q: Won't this add overhead for small features?**  
A: Yes, small 4-hour features (like toggle flag) skip full SDD. Use `/quick` command instead. Full SDD for 2+ day features.

**Q: What if ADRs are wrong mid-development?**  
A: ADRs can be revisited if reality diverges. Lock them, but don't carve in stone. Document change with rationale.

**Q: How do we handle new requirements mid-development?**  
A: Update spec via `/spec update [requirement]`. This cascades to dependent agents (recalc dependencies, update tests, etc).

**Q: Will developers actually follow the spec?**  
A: With context injected, why decisions are visible. Plus Silent Ops + Gate Runner enforce spec compliance automatically.

**Q: What if team disagrees on an ADR decision?**  
A: `/decide` allows async voting. Default to majority. If strong dissent, document trade-off + revisit in retrospective.
