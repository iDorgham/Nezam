## Context

v3.1 security posture: 50% health. Gaps:
- No automated SAST (static analysis)
- No dependency CVE automation beyond manual `pnpm audit`
- No secret scanning automation
- Two moderate CVEs documented but not tracked in CI

## Decision

Adopt **GitHub-native scanning** as the primary security automation layer — zero external service dependencies for the kit itself.

### Stack

| Tool | Trigger | Scope |
|---|---|---|
| **GitHub CodeQL** | PR + push to `Master` | JS/TS; severity: `critical` + `high` block merge |
| **GitHub DependaBot** | Weekly (Monday 07:00 UTC) | pnpm; auto-PR for patch/minor; major = manual review |
| **GitHub Secret Scanning** | All pushes | Repo-wide; push protection enabled |
| **`pnpm audit`** | Nightly + pre-release | Manual triage; `critical` = block release |

### Thresholds

| Severity | SAST | Dependency CVE | Action |
|---|---|---|---|
| Critical | Block PR | Block release | Immediate fix required |
| High | Block PR | Alert + 48h SLA | Fix before next release |
| Moderate | Advisory | Advisory | Document + schedule |
| Low | Ignored in CI | Ignored in CI | Backlog |

### Secret handling

- `.env.example` committed; `.env*` (except `.env.example`) in `.gitignore`
- `NEZAM_*` env prefix for all workspace config vars
- Rotation schedule: Auth0 keys quarterly; GitHub tokens on team change

### Security runbook

Created at `.nezam/core/docs/SECURITY_RUNBOOK.md`. Required content:
- Incident response procedure (discovery → containment → notification → recovery)
- Breach notification contacts
- How to force-approve a security exception (CTO sign-off required)

## Consequences

**Good:**
- Zero external service cost; GitHub-native
- CVE debt tracked automatically; no manual triage required for patch/minor
- Secret push protection prevents accidental leaks at commit time

**Bad / mitigated:**
- CodeQL analysis adds ~3 min to PR pipeline; runs async, does not block fast-path
- DependaBot major-version PRs require manual triage — assign to DevOps Lead weekly slot
