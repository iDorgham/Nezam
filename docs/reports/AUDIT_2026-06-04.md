# NEZAM + Design Hub — Audit, Progress & Release Plan

**Date:** 2026-06-04
**Auditor:** Claude (Systems Architect mode)
**Scope:** `.cursor/` canonical contracts, `.nezam/` runtime, Design Hub app, CI/CD, SDD plan structure, branch-policy, performance.
**Method:** Static analysis of the repo as it physically exists on disk (not as documented). All findings cite real file paths and line numbers.

---

## 0. Executive Summary

NEZAM is architecturally ambitious and largely coherent at the *contract* layer, but it has accumulated **structural drift** between what the contracts declare and what exists on disk. None of the issues are fatal, but four of them are **release-blocking** because they make the system's core promise — deterministic SDD execution — non-deterministic.

The performance complaint (Claude app > 30 GB RAM) has a concrete, addressable root cause: a **28-repo vendored `references/` tree** the desktop file-watcher indexes, plus **~25 duplicated design skills** and a 169-agent surface that defeats lazy-loading in practice.

| # | Issue | Severity | Release blocker? |
|---|-------|----------|------------------|
| C1 | Three-way SDD plan-root contradiction (`.nezam/core/plans/` vs `.nezam/core/plans/` vs `.nezam/core/plans/`) | **Critical** | Yes |
| C2 | Duplicate phase numbers on disk (`04-arch` + `04-design`, gap at `06`) | **Critical** | Yes |
| C3 | Four conflicting per-type numbering schemes in one rule file | **Critical** | Yes |
| C4 | ~25 duplicated design skills (prefixed vs unprefixed) | **High** | Yes |
| P1 | 28 vendored repos in `.cursor/design/references/` indexed by the app | **High** (perf) | No (but do it) |
| P2 | 169 agents + 220 skills defeat lazy-load in practice | **High** (perf) | No |
| B1 | Branch-policy documented but not *enforced* at commit/push | **Medium** | No |
| B2 | Stray `temp-merge-branch` in git refs | **Low** | No |

## 1. Audit Findings (detailed)

### C1 — Plan-root path is contradicted three ways

The canonical contracts disagree on where SDD plans live:

- **`.nezam/core/plans/` (singular)** — used by `.cursor/commands/start.md`, `.cursor/commands/plan.md`, `.cursor/state/schemas/plan_progress.schema.yaml`, `.cursor/commands/nezam.md` (declares `plans_root .nezam/core/plans/`).
- **`.nezam/core/plans/` (plural)** — used by ~8 design skills: `.cursor/skills/design/wireframe-pipeline/SKILL.md`, `design-to-code-handoff/SKILL.md`, `ux-research-protocol/SKILL.md`, `interaction-choreography/SKILL.md`, `design-token-architecture/SKILL.md`, `wireframe-catalog/SKILL.md`, `wireframe-to-spec/SKILL.md`, `design-iteration-protocol/SKILL.md`.
- **`.nezam/core/plans/`** — declared as the **new canonical** and `.nezam/core/plans/` explicitly called **legacy** by `.cursor/agents/swarm-leader.md:42`, `.cursor/agents/deputy-swarm-leader.md:36`, and `.cursor/commands/plan.md:629`.

**On disk, reality is a fourth state:** there is **no `.nezam/core/plans/` or `.nezam/core/plans/` directory at all** — only `.nezam/core/plans/` physically exists. So the commands and schemas write to a path that doesn't exist, the design skills write to a *second* path that doesn't exist, and the agents say both are wrong and only `.nezam/core/plans/` is correct.

**Impact:** any `/START`, `/PLAN`, or design skill run produces files in the wrong tree, hardlock prerequisite checks look in the wrong place, and the swarm leader's path-integrity guard fights the commands. This is the single biggest source of "the process feels broken/slow" — agents spend turns reconciling paths.

**Canonical decision (recommended): `.nezam/core/plans/`.** It already exists on disk, the swarm leaders enforce it, and it keeps user project plans out of the publishable `docs/` tree.

### C2 — Duplicate phase numbers in the real plan tree

`.nezam/core/plans/` on disk contains:

```
00-define  01-research  02-ia  03-content  04-arch  04-design  05-harden  07-build
                                            ^^^^^^^^^^^^^^^^^^^             ^^ gap (no 06)
plus: design/  plans-design/  scaffold/   ← un-numbered siblings
```

- **`04-arch` and `04-design` collide** on `04-`.
- **`06-` is missing** entirely (`05-harden` → `07-build`).
- **`design/`, `plans-design/`, `scaffold/`** are un-numbered orphans that duplicate numbered phases.

This is exactly the duplicated-numbers symptom you observed. It breaks any tool that sorts phases by prefix and makes "which phase am I in" ambiguous.

### C3 — Four conflicting numbering schemes in `sdd-pipeline-v2.mdc`

`.cursor/rules/sdd-pipeline-v2.mdc` (an `alwaysApply: true` rule) defines a *different* folder numbering per product type, where the **same number means a different phase**:

| Phase | Website | Web App | SaaS | Mobile |
|-------|---------|---------|------|--------|
| Architecture | `04-architecture` | `02-architecture` | `02-architecture` | `02-architecture` |
| IA | `02-ia` | `03-ia` | `03-ia` | `03-ia` |
| Design | `05-design` | `04-design` | `04-design` | `04-design` |
| Content | `03-content` | `05-content` | `05-content` | `05-content` |

The same file *also* references three different roots in its examples: `docs/workspace/plans/` (the structure blocks), `.nezam/core/plans/` (the monorepo block, line ~630), and `.nezam/core/plans/0N-build/` (the spec protocol, line ~699). So even the authoritative rule contradicts itself.

**This is the deepest root cause.** The on-disk collision (C2) is just the residue of an agent following one scheme while a command followed another.

### C4 — ~25 duplicated design skills

`.cursor/skills/design/` contains near-complete duplicate pairs: `accessibility-audit` **and** `nezam-accessibility-audit`; `design-tokens` **and** `nezam-design-tokens`; `wireframe-pipeline` **and** `nezam-wireframe-pipeline`; `design-to-code-handoff` **and** `nezam-design-to-code-handoff`; `ux-research-protocol` **and** `nezam-ux-research-protocol`; `interaction-choreography`, `wireframe-catalog`, `wireframe-to-spec`, `design-iteration-protocol`, `design-selector`, `design-md`, `component-library-api`, `css-architecture`, `dashboard-patterns`, `dashboard-ia-patterns`, `motion-3d`, `micro-interaction-designer`, `user-flow-mapper`, `visual-canvas-engine`, `brand-visual-direction`, `design-context-init` … and more.

The **unprefixed** copies are the ones writing the legacy `.nezam/core/plans/` paths (C1). The `nezam-` copies are the intended current generation. Keeping both:
- inflates the skill count (220 → ~25 are dead weight),
- bloats every context load and skill-router decision,
- and is the mechanism by which the wrong (legacy-path) skill gets picked.

### Other audit notes (non-blocking)

- **Multi-tool mirror sprawl:** the same agents/skills/commands are mirrored into `.claude/`, `.windsurf/`, `.opencode/`, `.codex/`, `.antigravity/`, `.antigravitycli/`, `.kilo/`, `.kilocode/`, `.gemini/`, `.qwen/`, `.agents/`, `.kiro/`. Generated from `.cursor/` via `pnpm ai:sync`. Correct in principle, but every mirror multiplies the on-disk file count the app watches (see P1/P2).
- **Root doc proliferation:** `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `KIRO.md`, `QWEN.md`, `VSCODE.md`, `WINDSURF.md` — all generated, all fine, but confirm `pnpm ai:check` passes so they don't drift.
- **`docs/` mixes product docs with SDD scaffolding:** `docs/DESIGN_HUB_UX_PLAN.md`, `docs/NEZAM_IMPROVEMENT_PLAN.md`, `docs/WIREFRAMES.md` sit next to `docs/reports/` and `docs/Nezam/`. Tolerable, but a cleanup target.

## 3. Performance Enhancement Plan

Your observation (Claude app > 30 GB RAM, slow runs) is explained by three compounding factors.

### P1 — The 28-repo `references/` tree (biggest lever)

`.cursor/design/references/` contains **28 full vendored open-source repositories**: `ruflo-main` (with an entire `v3/` monorepo), `BMAD-METHOD-main`, `builder-main`, `open-design-main`, `tailwindcss-main`, `shadcn-*`, `sketch-plugin-master`, `Silex-main`, `VvvebJs-master`, and more. Several carry their **own `node_modules`, `.yarn/releases`, and full git source**. `du`/`find` on this tree *timed out repeatedly* during the audit — a direct proxy for how heavy it is to index.

It is correctly listed in `.gitignore` (line 16) so it's not in history — but the **desktop app's file watcher still indexes every file on disk.** This is almost certainly the dominant RAM driver.

**Actions (in priority order):**
1. **Move `references/` out of the workspace** entirely — to `~/nezam-references/` outside the watched folder. Add a `scripts/fetch-references.sh` to re-hydrate on demand. *(Highest impact, lowest risk.)*
2. If they must stay, **strip nested `node_modules`/`.yarn`** from each vendored repo (`find references -name node_modules -type d -prune -exec rm -rf {} +` — run locally, not in the fragile sandbox).
3. Add the reference tree (and `.nezam/design-hub/node_modules`, `.next`, `tsconfig.tsbuildinfo`) to any **editor/indexer ignore** (`.vscode/settings.json` → `files.watcherExclude`, `search.exclude`).

### P2 — Surface area defeats lazy-loading

169 agents + 220 skills + 12 mirrored tool dirs = the file *count* the indexer tracks is enormous even before `references/`. The `agent-lazy-load.mdc` protocol only helps the *LLM context*; it does nothing for the **app's filesystem indexer**.

**Actions:**
1. **Dedup skills (C4):** removing ~25 duplicate design skills is a free 11% cut.
2. **Collapse mirrors for unused tools:** if you don't actively run Qwen/Kilo/Kiro/Antigravity-CLI day to day, stop syncing those mirrors (`pnpm ai:sync` config) — keep `.cursor`, `.claude`, and one or two others. Each removed mirror cuts ~400 files.
3. **Verify `AGENT_REGISTRY.yaml` is the only thing loaded at session start** (it's 945 lines — fine). Confirm no command force-loads all 169 agent files.
4. **Hardlocks are *not* the slowdown** — they're cheap YAML/markdown checks. The slowness is path-reconciliation (C1) + indexer pressure (P1/P2), not the gate logic.

### P3 — Two build contexts in one workspace

`.nezam/design-hub/` is a second Next.js app with its own `node_modules` + `.next` + `tsconfig.tsbuildinfo`. Combined with the root app, the indexer tracks two full dependency trees.

**Action:** ensure `.nezam/design-hub/node_modules`, `.next`, and `tsconfig.tsbuildinfo` are in `watcherExclude`. Consider making the design hub a proper workspace package so it shares one `node_modules` via pnpm.

**Expected outcome:** P1 alone should bring RAM from 30 GB+ toward normal (single-digit GB) for a project of this size.

## 4. SDD Plan Folder Reorganization

### 4.1 Decision: one root, one numbering scheme

- **Canonical root:** `.nezam/core/plans/` (already on disk; enforced by swarm leaders).
- **Numbering:** **one universal sequence**, product type changes *which phases are populated*, never the numbers. This kills C2 + C3 at once.

### 4.2 Target universal scheme

```
.nezam/core/plans/
├── 00-define/        PRD, PROJECT_PROMPT, specs/
├── 01-research/      SEO / market research
├── 02-ia/            information architecture
├── 03-content/       copy, content maps
├── 04-architecture/  stack, data model, API, auth, billing
├── 05-design/        tokens, components, wireframes, DESIGN_CHOICES
├── 06-scaffold/      PROJECT_SCAFFOLD
├── 07-build/         per-feature/per-page SPEC.md
├── 08-harden/        a11y, perf, security, SEO audits
└── 09-ship/          deploy checklist, monitoring
```

Per-type *order of execution* still differs (website is content-first, webapp is architecture-first) — but the **folder a phase writes to is fixed**. "Architecture is always `04-architecture`" regardless of whether it runs 2nd or 5th.

### 4.3 Migration of the current on-disk tree

| Current | Action |
|---------|--------|
| `04-arch/` | rename → `04-architecture/` |
| `04-design/` | rename → `05-design/` |
| `05-harden/` | rename → `08-harden/` |
| `07-build/` | rename → `07-build/` (keep) |
| `design/` | merge into `05-design/`, then delete |
| `plans-design/` | merge into `05-design/`, then delete |
| `scaffold/` | rename → `06-scaffold/` |
| (missing) | create empty `09-ship/` placeholder |

### 4.4 Contract fixes (the durable fix)

1. **`sdd-pipeline-v2.mdc`:** replace the four divergent folder trees with the one universal scheme above; keep the four *execution-order* tables. Fix the three root references in that file to all read `.nezam/core/plans/`.
2. **Global find/replace:** `.nezam/core/plans/` → `.nezam/core/plans/` and `.nezam/core/plans/` → `.nezam/core/plans/` across `.cursor/commands/`, `.cursor/rules/`, `.cursor/state/`, and `.cursor/skills/` (exclude `references/`). ~63 files touched.
3. **Dedup C4 first** so you only fix paths in the surviving `nezam-` skills.
4. Run `pnpm ai:sync && pnpm ai:check` to regenerate all mirrors + CLAUDE.md.
5. Add a CI guard to `sync-and-drift-check.yml`: grep for `docs/plans?/` outside `references/` and fail the build — prevents regression permanently.

## 5. Branch-Policy Compliance

### 5.1 Policy (from `.cursor/skills/external/nezam-git-workflow/SKILL.md`)

- Long-lived **`main`** (protected).
- Short-lived: **`feature/<spec-id>-slug`**, **`release/x.y.z`**, **`hotfix/x.y.z`**.
- `main`: required reviews ≥1, required checks, **linear history (no merge commits)**, dismiss stale approvals, signed commits where supported.

### 5.2 Compliance status

| Surface | Status |
|---------|--------|
| `git-automation.yml` | ✅ Compliant — rejects `branch`/`commit` in CI, dispatches only `tag`/`release`. |
| `release.yml` / `semantic-release.yml` | ✅ Release path matches `release/x.y.z` + annotated SemVer tags. |
| `/GIT branch` command (`commands/git.md`) | ⚠️ References "naming conventions" but **defines none inline** — the rule lives only in the skill. Relies on the human/agent remembering. |
| Git hooks (`.githooks/`, `.husky/`) | ⚠️ `pre-commit`, `post-commit`, `post-merge` exist — **none enforce branch naming**. No `pre-push` branch-name guard. |
| Live repo state | ⚠️ Stray `temp-merge-branch` in `.git/logs/refs/heads/` (B2) — violates the "short-lived, named" rule. |

### 5.3 Actions

1. **Add a `pre-push` hook** that rejects pushes from branches not matching `^(feature|release|hotfix)/` or `main`. Wire it through `.githooks/` (already the configured hooks path).
2. **Inline the naming regex** into `commands/git.md` so `/GIT branch` is self-contained and the agent can't drift.
3. **Add a CI branch-name gate** to `nezam-pr-gates.yml`: fail PRs whose head branch doesn't match the pattern.
4. **Delete the stray `temp-merge-branch`** ref.
5. Confirm GitHub branch protection on `main` matches the skill (linear history, required checks) — export the settings checklist the skill already calls for.

- [ ] `pnpm ai:sync && pnpm ai:check` green; `CLAUDE.md` regenerated.

### R2 — Performance + policy (high, ~1 session)
- [ ] **P1** Move/strip `references/` out of the watched workspace; add `fetch-references.sh`.
- [ ] **P2** Trim unused tool mirrors; add `watcherExclude` for references, design-hub `node_modules`, `.next`.

- [ ] **B2** Delete `temp-merge-branch`; export `main` branch-protection checklist.
- [ ] Re-measure Claude app RAM (target: single-digit GB).

### R3 — Release hardening (medium, ~1 session)
- [ ] Run full SDD pipeline end-to-end on one sample project per product type; confirm no path reconciliation occurs.
- [ ] `sdd-gate-enforcement.yml` + `design-gates.yml` + `wireframe-validation.yml` all green on the sample.

- [ ] Final `nezam-health-score` skill run; archive this report alongside the score.

### Suggested sequencing
R1 → R2 can overlap (different files), but **R1 must merge first** so R2's `ai:sync` regenerates from corrected contracts. R3 is the gate to tagging a release.
